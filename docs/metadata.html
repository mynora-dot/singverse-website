歌曲信息与审核

把文件名、平台候选和人工判断整理成可靠的歌曲资料。了解单曲审核、批量匹配、封面保存、自动应用与冲突恢复的完整流程。

内容核对：2026-11-15基于当前源码 · 功能以部署版本为准
本页内容

先分清三种信息

入口为“整理 → 歌曲信息”；单曲也可从“曲库 → 歌曲”的编辑、元数据刮削或“去复核”进入。同一审核工作台处理单曲与批次候选。

信息从哪里来你需要做什么
当前正式资料已保存的歌名、歌手、专辑、封面与人工决定作为核对基准
平台候选按关键词从已启用音乐平台查询确认是否同歌、同歌手、同版本
本次草稿选中的候选值、手工编辑与封面选择勾选要写入的字段，最后明确确认应用

配置音乐平台

  1. 进入“设置 → 音乐平台”，按需启用网易云、QQ、酷狗、酷我、汽水。
  2. 核对自动应用开关、相似度阈值和请求间隔，再保存设置。
  3. 回到歌曲信息，检查页面显示的实际设置摘要，再启动查询或批次。

新安装默认开启五个平台，自动应用默认关闭，阈值默认 80%，可设置 80%～100%。升级保留已保存配置。查询通常只发送歌名与歌手等关键词，不上传原始媒体，不使用平台账号 Cookie。

保存平台设置会暂停活动批次。批次记有创建时的配置快照，页面的全局开关与已有批次快照可能不同；关闭全局自动应用或提高全局阈值，仍会限制旧批次的自动写入。

单曲审核：一步步确认

  1. 打开歌曲工作台，先核对当前歌名、歌手与版本。需要时展开文件信息。
  2. 选择已启用平台，输入更准确的关键词并搜索；遇到同名曲，可加入歌手或版本词。
  3. 选择候选，对照当前值、候选值和编辑值。高分是字符串相似度参考，不是正确率。
  4. 按需手工编辑歌名、歌手、专辑、发行日期、别名、平台时长；没有平台也能手工整理。
  5. 选择封面，勾选本次要应用的有效字段，检查“将修改”的已有值。
  6. 点击确认应用，等待服务端返回结果。仅保存子窗口编辑或选中候选都只是草稿。

达到阈值的第一候选可以自动选中，单曲仍不会自动写入。候选缺失值、未选字段不会清空现有资料。平台时长是参考信息，不等于本地媒体实际时长。

封面：选择、上传与保存

可从歌曲候选、额外封面搜索或本地 JPEG/PNG 选择。平台默认原图，可选平台提供的高清版本，加载成功后显示实际像素；浏览器缩小预览不会把正式原图压成缩略图。

  • 上传完成只表示图片已进入受管存储；选入草稿并确认应用后，才成为歌曲封面。
  • 当前原图与资料包标准支持最多 32 MiB、67,108,864 像素，实际入口以部署版本校验为准。
  • 封面读取失败不应清空已确认文本，可换图或稍后重试。
  • 正式封面和歌词是持久资料；备份时保留数据库及对应资料目录，不能当临时缓存清空。
  • 替换封面不会修改原媒体，也不会删除其他歌曲使用的图片。

批量匹配与范围

可选择当前页歌曲启动批次，或在歌曲信息页选择全库、单个来源。批次范围不自动继承歌曲列表的所有筛选条件，提交前核对说明。

  • 指定歌曲一次最多 500 首；全库或来源批次最多 5000 首，超限应拆分。
  • 已有有效确认资料且文件未变化的歌曲可跳过；需要重新核对时使用单曲入口。
  • 进入批次后可搜索、排序、按待处理、待审核、已应用、失败、跳过等状态查看。
  • 支持暂停、继续、终止及允许状态下逐项重新匹配。终止保留已有结果与候选，不能继续原终止批次。
  • 历史批次通过任务中心或批次深链接查找，业务页不会把所有历史批次铺成同一个列表。

读懂“匹配完成”和进度

显示真实含义
待处理 / 处理中还没有结果，或本次请求正在执行
待审核查询过程结束，但还未人工确认写入
已应用本次自动或人工确认已经写入
失败这一轮处理结束并遇到错误，可按提示重试
跳过已存在有效确认资料，本轮保留
处理进度待审核 + 已应用 + 失败 + 跳过，占全部检查歌曲的比例

因此 100% 表示本轮检查处理结束，并不保证每首已写入。重试会把条目放回待处理，进度可能降低。终止批次的进度可以不足 100%，不会把剩余歌曲假装处理成功。

批次审核与自动应用

从批次的“审核候选”进入，可在确认写入后同步更新该批次明细。若通过独立单曲入口手工处理，正式资料会更新，但不会追溯改写旧批次的审核历史。

自动应用仅在明确启用的条件下运行，第一候选达到有效阈值即可采用；即使标为“高相似度”，仍要符合当前全局开关与更高阈值。重新匹配前应核对该批次是否允许自动写入。

人工订正、重扫与版本冲突

人工确认优先于文件标签、自动任务和共享更新。正式资料区分设置、明确清空与解除本机决定；普通审核不把空白字段当作删除命令。源文件变化主要使相关技术证据重新待核验，不会让整份人工资料消失。

确认时会检查资料修订、候选归属和素材指纹。版本冲突返回 409 时，保留草稿，重新读取并核对；超时不确定时使用原提交重试，避免重复写入。候选七天后过期，需要重新搜索。

限流、暂停和失败恢复

同平台请求串行，启动间隔至少 1.5 秒；后台每首额外等待默认 1～2 秒，可配置 0～300 秒。HTTP 429 至少冷却 60 秒，等待后再重试。随机等待只是平滑请求，不保证绕过平台限制。

部分平台失败时，其余成功候选仍可审核。服务重启后运行批次恢复为暂停，先核对平台配置再继续。暂停或终止可能无法撤回已经发出的网络请求，但提交前会复核状态。
