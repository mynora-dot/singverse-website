## 缓存存在哪里 {#cache}

“设置 → 存储与缓存”管理 Go 侧受控原片缓存和兼容播放结果。生成器给出初始容量，后台保存后的设置会优先，修改环境变量不一定覆盖现有策略。

原片缓存可能只有部分数据，不能因为已有缓存就断定整首可离线播放。同一歌曲的不同画质、音轨或字幕参数也可能产生多份结果。

## 清理前分清数据 {#cleanup}

| 数据 | 是否可作为普通缓存处理 |
| --- | --- |
| 播放页面管理的缓存条目 | 按使用状态和保护策略清理 |
| 下载目录里的歌曲 | 真实媒体，纳入备份 |
| 数据库与主密钥 | 核心持久数据，成套保存 |
| 模型文件 | 重下载/转换成本高，按用途保留 |
| 计算工作目录 | 还含硬件、模型和试跑设置，不能整目录随意删 |

优先使用后台受控清理。正在使用、受保护或仍有引用的文件可能暂不可清；以实际清理结果和磁盘占用为准，不手动删除正在写入的文件。

## 计算服务 {#compute}

“设置 → 计算服务”统一维护节点连接、视频策略和音频模型。更换硬件后重新检测与试跑，参数说明见[部署手册](/docs/parameters.html)，具体操作见[计算服务](/docs/compute.html)。

## AI 与助手 {#ai}

AI 连接是需要管理员配置的外部服务，不包含在 Docker 镜像里。按页面填写服务地址、模型和密钥，测试后再启用对应能力。发送到外部服务的内容按具体功能确认，不上传整套曲库或密钥来排障。

当前助手区域的展示不等于已经开放完整对话和工具执行能力。以实际页面可用入口为准，不能把设置成功写成所有 AI 功能都能使用。

## 电视首页与分类 {#tv-home}

“客厅 → 电视首页”保存共享首页文案、封面和展示设置；“整理 → 歌曲分类”维护实际分类。修改后由客户端读取更新，不能通过刷新官网改变 NAS 中的配置。原始媒体、手机作品与设备本地偏好各有独立存储位置。
