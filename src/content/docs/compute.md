## 什么时候需要计算端 {#need}

计算端处理媒体探测、兼容播放、音轨分析与伴奏模型。Go 保持唯一业务数据库写入者，客户端始终访问 Go。只部署管理端可以管理业务设置，但需要计算的功能要等节点可用。

## 同机自动连接 {#connection}

生成器选择“管理端 + 同机计算”时，两服务位于同一 Compose 网络，Go 使用 `http://singverse-compute:8090`，回调为 `http://singverse-go-backend:8080`。共享 `singverse-compute-auth` 目录由节点生成 token、Go 只读获取，不用复制密钥。

到“设置 → 计算服务”检查连接方式。已有数据库可能保存手动地址或禁用状态，此时改环境变量不会覆盖后台设置。选择自动连接后查看节点状态、版本和能力。

## 独立节点与回调 {#remote}

在另一台 Linux 主机选择生成器“独立计算节点”，下载并启动配置。它只运行 compute，默认发布宿主 18090 并开启局域网配对。业务主机可选择“仅管理端”，然后在“设置 → 计算服务”使用配对或手动连接流程。

两条链路都必须可达：Go → 节点用于提交任务；节点 → Go 用于授权读取素材和上传结果。回调填写节点能访问的业务根地址，如 `http://NAS局域网IP:18080`，不要使用远端容器无法解析的 `singverse-go-backend` 或其自己的 localhost。

同名目录不会在两台机器之间自动同步 token。健康检查成功仅证明节点 HTTP 可达，不能代替认证或真实回源。跨网络部署需使用受控网络与正确的 HTTPS 入口。

## 视频后端与模型是两项设置 {#hardware}

视频选择 NVENC、VAAPI、QSV 或 MPP；音频按镜像运行库与模型能力选择。部署默认由环境变量给出，后台保存的选择优先。迁移主机后检查实际硬件、选择“跟随部署”或明确后端并重新试跑。

每种硬件的设备、运行库和限制见[硬件指南](/docs/hardware.html)。仅在 FFmpeg 列表里出现编码器，不代表驱动、硬解、色调映射和真实素材都能运行。

## 下载模型与试跑 {#models}

1. 确认计算节点已连接并完成环境检测。
2. 在计算服务的模型区域下载/导入需要的固定模型。快速识别模型、htdemucs、MDX 并非同一个文件。
3. 完成独立 CPU 试跑及目标加速后端试跑；RKNN 转换文件按硬件页手工准备。
4. 先处理一首短歌，查看任务实际 backend 和降级原因，再扩大批量。

资格与当前模型、镜像和运行环境相关，重启后的环境检查或变更可能使旧资格失效。程序保留真实未就绪状态，不能靠反复点击选择跳过试跑。

## 失败和抢占 {#failure}

视频与音频共用 CPU 自动降级策略。加速故障是否重试 CPU 取决于开关及已通过的 CPU 资格；关闭后失败保持失败。磁盘不足、无效素材、取消等问题需要分别排查，不能用降级掩盖。

实时播放会优先使用计算资源，音频任务可能被抢占或取消。查看任务原因后安排空闲时重试。容器 healthy、GPU 枚举与模型加载只是部分证据，最终以任务结果与实际播放为准。
